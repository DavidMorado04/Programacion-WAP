LAB: FILE PATH TRAVERSAL, TRAVERSAL SEQUENCES BLOCKED WITH ABSOLUTE PATH BYPASS

Autor: David Campos Morado - 183511 | Ingeniería en Tecnologías de la Información
Profesor: Servando Lopez Contreras

Objetivo del Laboratorio

Identificar y explotar una vulnerabilidad de File Path Traversal en una aplicación web que implementa una defensa incompleta. Se busca evadir el filtro que bloquea las secuencias de navegación relativa (como ../) utilizando una técnica de Absolute Path Bypass para lograr leer el archivo /etc/passwd del servidor.

Marco Teórico

File Path Traversal: Es una vulnerabilidad que permite a un atacante leer archivos del servidor al manipular las rutas de acceso construidas a partir de la entrada del usuario sin la validación adecuada.

Absolute Path Bypass: Muchas aplicaciones intentan defenderse filtrando secuencias como ../. Sin embargo, si el código pasa el parámetro a una API de lectura de archivos sin verificar si la ruta es absoluta, el atacante puede referenciar el archivo objetivo directamente desde la raíz del sistema (ej. /etc/passwd), ignorando el directorio base y evadiendo el filtro.

Desarrollo de la Práctica (Procedimiento y Evidencias)

Paso 1: Análisis del entorno y objetivo
Se ingresó a la plataforma de PortSwigger para revisar las instrucciones del laboratorio, el cual indica que las secuencias de salto de directorio están bloqueadas y pide recuperar el contenido del archivo /etc/passwd.

Paso 2: Preparación e Intercepción con Burp Suite
Se inició Burp Suite configurando un proyecto temporal. Con el proxy activado (Intercept is on), se navegó por la tienda para capturar las peticiones HTTP. Se identificaron las peticiones GET al endpoint /image, utilizando el parámetro filename para cargar las imágenes de los productos.

Paso 3: Comprobación del filtro de seguridad
Se intentó realizar un ataque clásico inyectando el payload ../../../etc/passwd en el parámetro filename. La respuesta del servidor fue un error 400 Bad Request, lo que confirma que la aplicación bloquea correctamente las secuencias de punto-punto-barra (../).

Explicación del Payload y Resultados

Análisis del Payload:

GET /image?filename=/etc/passwd
  • A diferencia de un path traversal simple, no se emplearon secuencias relativas (../) porque el servidor las bloquea.
  • El filtro del servidor actúa únicamente sobre un patrón de caracteres conocido, pero no verifica la forma completa de la ruta resultante ni valida si el valor recibido es una ruta absoluta en sí misma.
  • Al enviar /etc/passwd, el sistema de archivos subyacente interpreta la barra inicial (/) como la raíz absoluta, ignorando cualquier intento del servidor de concatenarlo a su directorio base de imágenes.

Resultados Obtenidos:

  • Se logró explotar exitosamente el endpoint /image evadiendo el filtro de secuencias.
  • El servidor devolvió una respuesta HTTP 200 OK cuyo cuerpo contenía el archivo completo /etc/passwd, evidenciando las cuentas del sistema (root, daemon, bin, sys, etc.).
  • Esto demuestra que una defensa parcial es insuficiente si no se complementa con una validación integral de la ruta resultante (Absolute Path Bypass).

Conclusión

La resolución de este laboratorio demuestra que implementar filtros de seguridad basados únicamente en listas negras (como bloquear la cadena ../) proporciona una falsa sensación de protección. Para mitigar esta vulnerabilidad de forma efectiva, es necesario implementar validaciones mediante listas blancas (permitiendo solo caracteres alfanuméricos y extensiones específicas) y verificar a nivel de código que la ruta canónica final del archivo no escape del directorio asignado para la aplicación.
