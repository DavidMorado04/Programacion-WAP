ACTIVIDAD 07

Explotando un Path Traversal con Burp Suite

Documentación del laboratorio "File path traversal, simple case": interceptación de la solicitud, manipulación controlada del parámetro filename y validación del resultado.

Objetivo del Laboratorio

Identificar y explotar de manera controlada una vulnerabilidad de File Path Traversal presente en la carga de imágenes de una aplicación web. Mediante Burp Suite, se analizó y modificó una petición HTTP para manipular el parámetro filename utilizando secuencias de recorrido de directorios, con el objetivo de acceder al archivo /etc/passwd y comprobar la falta de validación adecuada de las rutas proporcionadas por el usuario.

Marco Teórico y Fundamentación Técnica

El File Path Traversal (también conocido como Directory Traversal) es una vulnerabilidad web que permite a un atacante leer archivos arbitrarios en el servidor que ejecuta la aplicación. Esto ocurre típicamente cuando una aplicación web utiliza parámetros enviados por el usuario (como el nombre de un archivo de imagen) para abrir o cargar un recurso sin validar o sanitizar la entrada previamente.

Impacto (CIA): Esta vulnerabilidad afecta directamente a la Confidencialidad de la información. Mediante el uso de secuencias de escape como ../../../, un atacante puede ascender desde la carpeta pública de la aplicación hasta la raíz del servidor, logrando acceder a archivos críticos del sistema (como /etc/passwd en Linux), código fuente o archivos de configuración con credenciales. Esto a menudo sirve como vector inicial para escalar privilegios o ejecutar código remotamente (RCE).

Desarrollo y Procedimiento

El laboratorio se realizó en PortSwigger Web Security Academy utilizando Burp Suite Community Edition. Desde el navegador integrado de Burp Suite se accedió a la instancia del laboratorio y se analizaron las peticiones HTTP generadas por la aplicación.

En Proxy > HTTP history se identificó que las imágenes de los productos eran solicitadas mediante peticiones GET al endpoint /image, utilizando el parámetro filename para especificar el archivo que debía recuperar el servidor. A partir de este comportamiento se seleccionó una de las peticiones para analizar y modificar su contenido.

Análisis de la petición con Repeater: La petición seleccionada se envió al módulo Repeater, permitiendo modificar manualmente sus parámetros y reenviarla al servidor sin necesidad de generar nuevamente la solicitud desde el navegador.

[ FIGURA 1: Petición HTTP GET original interceptada mostrando el parámetro filename. ]

Explotación y Análisis del Payload

Dentro de Repeater se sustituyó el valor original de filename por el siguiente payload malicioso:

filename=../../../etc/passwd

Explicación del payload:

  • Cada secuencia ../ permite retroceder un nivel dentro de la estructura de directorios. Su repetición permite ascender varios niveles, abandonar el directorio destinado a las imágenes e intentar alcanzar la raíz del sistema de archivos.
  • /etc/passwd indica el archivo crítico del sistema Linux que se desea recuperar. En conjunto, el payload aprovecha la ausencia de una validación adecuada para construir una ruta que termina apuntando fuera del webroot.
[ FIGURA 2: Inyección del payload en el parámetro filename a través de Burp Suite Repeater. ]

Respuesta Vulnerable y Confirmación

Después de enviar la petición modificada, el servidor respondió con un HTTP/2 200 OK y devolvió en el cuerpo de la respuesta el contenido del archivo /etc/passwd.

El resultado confirmó que la aplicación procesaba las secuencias de recorrido incluidas en filename sin restringir adecuadamente el acceso al directorio destinado a las imágenes. De esta manera fue posible acceder a un archivo del sistema ubicado fuera de la ruta autorizada.

[ FIGURA 3: Respuesta vulnerable del servidor mostrando el contenido de /etc/passwd. ]

Finalmente, PortSwigger Web Security Academy reconoció la recuperación correcta del archivo solicitado y marcó el laboratorio como Solved, confirmando que el objetivo de la práctica había sido completado satisfactoriamente.

[ FIGURA 4: Confirmación oficial de la plataforma indicando "Lab Solved". ]

Mitigación Recomendada

La forma más efectiva de prevenir vulnerabilidades de Path Traversal es evitar pasar a las APIs del sistema de archivos cualquier entrada proporcionada por el usuario.

Si es estrictamente necesario utilizar entradas del usuario, se debe implementar una verificación con ruta canonical. La aplicación debe resolver la ruta absoluta del archivo solicitado (eliminando secuencias como ../) y validar programáticamente que esta ruta limpia comience exclusivamente con el directorio base autorizado antes de procesar la solicitud.
