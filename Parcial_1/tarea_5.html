Actividad 05: De la teoría a la práctica: Walkthrough en acción

> Introducción

El desarrollo de esta actividad tiene como propósito demostrar la aplicación práctica de los conceptos teóricos de seguridad informática mediante un walkthrough técnico detallado[cite: 2]. A través de la evaluación de un entorno controlado en la máquina virtual "Snakeoil", se exploran metodologías orientadas a la identificación de vulnerabilidades web, la manipulación de peticiones en APIs REST y la extracción de información sensible[cite: 2].

> Configuración del Escenario y Laboratorio

La práctica se estructuró utilizando un entorno de pruebas aislado en Oracle VirtualBox mediante un adaptador de red tipo "Solo anfitrión" (Host-Only)[cite: 2]:

  • Segmento de Red: Segmento 192.168.56.0/24 con servidor DHCP activo[cite: 2].
  • Máquina Atacante: Kali Linux (configurada en las IPs 192.168.56.3 y 192.168.56.4)[cite: 2].
  • Máquina Víctima: Máquina virtual vulnerable "Snakeoil" operando en la dirección IP 192.168.56.5[cite: 2].
  • Servicios Detectados: Tras el escaneo inicial, se identificaron servicios expuestos en los puertos 22 (OpenSSH) y los puertos 80 y 8080 (Nginx)[cite: 2].

> Evidencias y Comandos de Ejecución

Durante el proceso de auditoría y explotación del objetivo, se ejecutaron las siguientes herramientas y comandos principales:

  • Descubrimiento de Red (Netdiscover): Comando utilizado para escanear y localizar de manera dinámica la IP de la máquina víctima en la red interna aislada. 
    netdiscover -r 192.168.56.0/24
  • Escaneo de Puertos y Servicios (Nmap): Análisis detallado para identificar versiones de software y servicios activos en el objetivo. 
    nmap -sC -sV 192.168.56.5
  • Enumeración de Directorios Web (Gobuster): Herramienta empleada para mapear los endpoints ocultos de la API en el puerto 8080, localizando rutas críticas como /users, /registration, /login, /secret y /run[cite: 2]. 
    gobuster dir -u http://192.168.56.5:8080 -w /usr/share/wordlists/dirb/common.txt
  • Manipulación y Proxy (Burp Suite): Se interceptó la petición hacia /registration que arrojaba un error Wrong Method!!! al intentar consultarla por GET, enviándola al Repeater para forzar el verbo HTTP a POST[cite: 2].
  • Explotación y Extracción de Secretos: Al inyectar un payload URL-encoded con las credenciales (username=morado&password=morado4), se obtuvieron tokens JWT y se forzó la exposición de fragmentos del código fuente del backend (app.py)[cite: 2]: 
app = Flask(__name__)
api = Api(app)
app.config['SECRET_KEY'] = 'snakeoilisnotgoodforcorporations'
app.config['JWT_COOKIE_SECURE'] = True
app.config['JWT_SECRET_KEY'] = 'NOreasonableDOUBTthisPASSWORDisGOOD'
app.config['JWT_ACCESS_TOKEN_EXPIRES'] = timedelta(minutes=15)
app.config['JWT_REFRESH_TOKEN_EXPIRES'] = timedelta(hours=1)
app.config['JWT_TOKEN_LOCATION'] = ['cookies']
app.config['JWT_COOKIE_CSRF_PROTECT'] = False
app.config['SQLALCHEMY_DATABASE_URI'] = 'sqlite:///app.db'
app.config['SQLALCHEMY_TRACK_MODIFICATIONS'] = False

> Controles de Seguridad y Conclusión

Para mitigar las vulnerabilidades expuestas en este tipo de arquitecturas, se proponen los siguientes controles defensivos:

  • Control de Acceso Basado en Roles (RBAC): Restringir el acceso a endpoints sensibles de registro y administración para evitar altas de usuarios sin autorización[cite: 2].
  • Sanitización y Validación de Entradas: Asegurar un correcto filtrado en el backend que valide adecuadamente los métodos y verbos HTTP permitidos[cite: 2].
  • Protección de Secretos: Mantener las claves maestras y configuraciones críticas (SECRET_KEY) fuera del código fuente, utilizándose mediante variables de entorno seguras[cite: 2].

Conclusión: La práctica demostró con éxito que cuando los mecanismos de fuerza bruta estricta fallan debido a la alta complejidad algorítmica (como PBKDF2), la revisión lógica de las aplicaciones web y la manipulación de peticiones mediante proxies facilitan rutas alternativas de intrusión y auditoría[cite: 2].
